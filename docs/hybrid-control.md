# 语义匹配与混合填写

实现目标：用户明确点击“AI 理解并预览”后，模型结合字段标题、说明、分区和记录身份进行语义映射，不要求字段同名。规则匹配作为离线入口及 API 失败时的保守预览。

## 执行路径

1. 扫描可编辑字段和关联上下文，识别重复经历的学校、公司或项目身份；相同标签属于不同经历时，不仅依赖序号。
2. 模型只返回已有简历事实的路径。先预览，再对勾选项执行 DOM 填写并读回。
3. 可选浏览器输入控制：扩展在 manifest 声明 `debugger` 权限（Chrome 不允许该权限作为 optional_permissions），用户在扩展弹窗主动启用控制功能。DOM 失败时，使用浏览器原生输入事件与点击；功能关闭时仍可使用 DOM。
4. 可选视觉兜底：用户勾选后，仅在当前字段失败时，将当前页面截图、目标事实和允许的候选发往已配置 API。模型需要支持图片。每步重新观察，只接受当前字段或关联菜单范围内的有界动作，不执行模型代码。
5. 有限次重试、逐项读回、支持停止；最终保存或提交由用户进行。

## 状态与隐私

- 控制功能默认关闭；启用并连接目标页时 Chrome 显示调试提示。弹窗可关闭控制；安装所声明的调试权限无法运行时撤销，需要停用或卸载扩展。
- 权限依据：[Chrome permissions 官方文档](https://developer.chrome.com/docs/extensions/reference/api/permissions)，debugger 属于不能声明为可选的权限。
- 截图可能包括页面上的个人信息；仅当前操作选择视觉兜底时发送，不写入仓库或持久日志。
- API 密钥只保留在后台配置；控制请求由后台从所选简历的 `sourcePath` 重新读取事实，页面不能传入任意替代文本或 CDP 命令。
- 浏览器控制结束后释放调试连接。已有调试工具占用时明确失败，不抢占。
- 填写后保留仍为空的字段对应 AI 计划，分别显示“空字段数”和“已匹配数”；复扫不暗中再次请求 API。

## 适用范围

这是一套通用执行框架，不保证全部网站适配。跨域 iframe、关闭的 Shadow DOM、无法确认归属的弹层、验证码、画布或不提供可验证状态的控件仍可能需要人工完成。视觉不能绕过目标范围、资料真实性或最终提交边界。
